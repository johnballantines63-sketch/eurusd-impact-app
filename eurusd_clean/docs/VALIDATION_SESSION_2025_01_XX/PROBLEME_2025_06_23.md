# Problème Détection Pattern 2025-06-23

**Date** : 2025-01-XX  
**Problème** : Pattern détecté comme NONE alors que le CSV indique DOUBLE_WAVE  
**Cause** : Le détecteur utilise toujours 14:30 alors que l'événement réel est à 15:45

---

## 🔍 PROBLÈME IDENTIFIÉ

### Événements réels pour 2025-06-23 :
- **09:30** : PMI Flash DE (3 événements)
- **15:45** : PMI Flash US (3 événements) ← **Événement principal**

### CSV de validation indique :
- **Anchor time** : 16:00
- **Pattern** : DOUBLE_WAVE
- **Wave1 peak** : 16:27
- **Pullback** : 16:49
- **Wave2 peak** : 16:56
- **Impact réel** : 83.9 pips

### Détecteur actuel :
- **Baseline** : 14:29 (mode `prev_close_14_29`)
- **Hint** : 14:30 (forcé dans le code ligne 93)
- **Résultat** : Pattern NONE (Peak2 n'a pas dépassé Peak1)

**Cause** : Le détecteur cherche le pattern à partir de 14:30, mais le mouvement réel commence à 15:45.

---

Le graphique montre une **forte montée dans l'après-midi** (14:00-22:00) :

## ✅ SOLUTION PROPOSÉE

### Option 1 : Modifier le détecteur pour accepter l'anchor_time réel

**Modification** : Ajouter un paramètre `event_time` ou `hint_ts` à `detect_for_date_duckdb_rev12` et `detect_double_wave_on_df_rev12`.

**Code** :
```python
def detect_for_date_duckdb_rev12(
    db_path: str, table: str, date: datetime,
    tz: str = DEFAULT_TZ,
    baseline_mode: str = DEFAULT_BASELINE_MODE,
    minutes_after_hint: int = SCAN_MINUTES_AFTER_HINT,
    trading_window: bool = True,
    debug: bool = False,
    event_time: Optional[datetime] = None  # NOUVEAU : Heure réelle de l'événement
) -> Optional[Dict]:
    # ...
    if event_time is not None:
        hint_ts = pd.Timestamp(event_time, tz=tz)
    else:
        # Fallback : utiliser 14:30 par défaut
        hint_ts = ts.replace(hour=14, minute=30, second=0, microsecond=0)
```

**Dans le pipeline** :
```python
pattern_real_result = detect_for_date_duckdb_rev12(
    db_path=str(self.db_path),
    table='prices_finnhub_m1',
    date=pattern_date,
    tz='Europe/Zurich',
    baseline_mode='prev_close_14_29',
    minutes_after_hint=120,
    trading_window=True,
    debug=False,
    event_time=anchor_time  # NOUVEAU : Passer l'anchor_time réel
)
```

### Option 2 : Utiliser le pattern détecté par critères événements si pattern réel échoue

**Logique** : Si le pattern réel n'est pas détecté mais que les critères événements sont remplis, utiliser le pattern basé sur les critères événements.

**Code** :
```python
if pattern_real_result and pattern_real_result.get('double_wave', False):
    # Pattern réel confirmé
    is_double_wave = True
elif is_double_wave_events:
    # Critères événements remplis mais pattern réel non détecté
    # → Utiliser pattern basé sur critères événements (comme validation 27 nov 2025)
    is_double_wave = True
    self._log(f"   ⚠️ Pattern réel non détecté mais critères événements remplis → Utiliser Double Wave", "WARNING")
```

## 📝 RECOMMANDATION

**Option 1** est préférable car elle permet de détecter correctement le pattern réel dans les prix, même si l'événement n'est pas à 14:30.

**Option 2** est un fallback acceptable si l'Option 1 est trop complexe à implémenter.
